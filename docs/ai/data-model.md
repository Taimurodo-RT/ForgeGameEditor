# Модель данных

Формат данных ИИ жителей и состояния рантайма в Forge. Данные лежат в папке проекта Forge, в `game/villagers/`. Переписано 30.10.2026: привязка к Godot убрана, контракт с игрой теперь один манифест Forge (раздел «Манифест»).

## Принципы

- **Данные описывают смысл.** В файлах ИИ нет путей объектов сцены, пикселей и имён кода. Анимация, звук и точка на карте задаются логическим именем, а что за ним стоит, решает модуль игры Forge.

- **Один ресурс на файл.** JSON в UTF-8, ключи в алфавитном порядке, отступ 2 пробела, перевод строки LF. Редактор всегда пишет файл в этом каноническом виде, поэтому diff в git показывает только настоящие правки.

- **Стабильные id.** Ресурс, нода, порт и фаза имеют id, который не меняется при переименовании. Отображаемое имя хранится отдельно ключом локализации.

- **Одни единицы везде.** Время в целых игровых минутах, расстояние в клетках карты, потребности от 0 до 100, полезность от 0 до 1. Перевод клеток в пиксели делает модуль «Жители».

- **Детерминизм.** Числа в данных имеют не больше 4 знаков после запятой. Рантайм хранит значения в фиксированной точке Q16.16, а B и S считает в Q32.32. Числа из JSON переводятся в фиксированную точку один раз, при сборке пакета, округлением к ближайшему (половина к чётному). Кривые-формулы запекаются в таблицы, ступеньки и кривые по точкам считаются точно. Поэтому результат не зависит от процессора и компилятора. Порядок обхода любых коллекций задан сортировкой по id.

**Правила счёта.** Каждая операция над числами с фиксированной точкой округляет результат к ближайшему, половина к чётному; других режимов нет.

- Умножение Q16.16: произведение в `i64`, сдвиг на 16 бит с округлением. Умножение Q32.32: то же в `i128`, сдвиг на 32.
- Деление: делимое сдвигается влево в более широком типе, остаток округляет результат по тому же правилу. Нулевые знаменатели не пропускает валидатор; если ноль всё же получился, результат насыщается до границы типа, а в журнал пишется предупреждение.
- Переполнение насыщается до границы типа, перехода через ноль нет.
- Формула B: соображения перемножаются в порядке их id в графе действия; компенсация 1/n применяется к каждому соображению до умножения; каждый шаг округляется.
- Кривая по точкам: `y = y0 + (y1 − y0) · (x − x0) / (x1 − x0)`, числитель в широком типе, одно деление и одно округление.
- Все операции живут в одном модуле чисел `forge-ai/src/num.rs` с тестами граничных случаев; остальной код не умножает и не делит числа напрямую.
- `serde_json` подключается без фичи `preserve_order`. Журнал и хэши строятся из `BTreeMap` и структур с фиксированным порядком полей, а тест в `forge-ai` ловит, если фичу включил другой crate.

- **Строгая валидация.** Неизвестное поле в файле считается ошибкой, а не игнорируется. Свободные данные для своих нужд идут только в поле `meta`, которое рантайм не читает.

- **Формальная схема.** Каждая таблица ниже воплощается в JSON Schema (draft 2020-12) в папке `schema/v1/`. Источник истины один: типы Rust генерируют схему, а редактор и валидатор читают её.

## Базовые типы

| Тип           | В JSON | Ограничения                                                                                                    | Пример                         |
|---------------|--------|----------------------------------------------------------------------------------------------------------------|--------------------------------|
| `Id`          | строка | `вид.имя`, регулярное выражение `^[a-z]+\.[a-z][a-z0-9_]*(\.[a-z0-9_]+)*$`, до 64 символов, уникален в проекте | `action.eat`                   |
| `LocalId`     | строка | `^[a-z][a-z0-9_]*$`, до 32 символов, уникален внутри родителя (нода, порт, фаза, слот)                         | `n_hunger_curve`               |
| `Ref<Вид>`    | строка | `Id`, префикс обязан совпадать с видом, цель обязана существовать                                              | `need.food`                    |
| `Int`         | целое  | от −2³¹ до 2³¹−1                                                                                               | `3`                            |
| `Real`        | число  | не больше 4 знаков после запятой, от −32768 до 32767                                                           | `1.25`                         |
| `Unit`        | число  | `Real` от 0 до 1                                                                                               | `0.1`                          |
| `NeedValue`   | число  | `Real` от 0 до 100                                                                                             | `55`                           |
| `Minutes`     | целое  | игровые минуты, ≥ 0                                                                                            | `30`                           |
| `TimeOfDay`   | строка | `ЧЧ:ММ`, от `00:00` до `23:59`                                                                                 | `18:00`                        |
| `DateSpec`    | объект | `{season, day}` или `{every_days, offset}` по календарю проекта                                                | `{"season":"autumn","day":10}` |
| `Tiles`       | число  | `Real` ≥ 0, в клетках карты                                                                                    | `12`                           |
| `TileOffset`  | массив | `[x, y]` из `Real`, смещение от точки привязки объекта                                                         | `[1, 0]`                       |
| `LocKey`      | строка | `loc.` + путь, строка обязана быть в `loc/ru.json`                                                             | `loc.action.eat.name`          |
| `Tag`         | строка | `^[a-z][a-z0-9_]*$`, список допустимых тегов в `project.json`                                                  | `food`                         |
| `LogicalName` | строка | имя анимации, звука или эффекта без привязки к коду, обязано быть в манифесте                                    | `eat`                          |
| `Enum<…>`     | строка | одно из перечисленных значений                                                                                 | `life`                         |

Виды в префиксе id перечислены в следующем разделе. Переименование id делает только редактор: он правит все ссылки и добавляет запись в `renames.json`, чтобы старые сохранения игры продолжали загружаться.

## Схемы основных ресурсов

Поля шапки (`id`, `schema`, `name`, `tags`, `meta`) в таблицах не повторены. «Да» в колонке «Обяз.» означает, что без поля файл не проходит валидацию; у необязательных полей указано значение по умолчанию.

### action

| Поле            | Тип                                                                               | Обяз. | Правило                                 |
|-----------------|-----------------------------------------------------------------------------------|-------|-----------------------------------------|
| `category`      | `Enum<eat, sleep, work, leisure, social, idle, survival, event>`                  | да    |                                         |
| `bucket`        | `{default: LocalId группы, overrides: список {when: Condition, bucket: LocalId}}` | да    | Первое совпавшее правило побеждает      |
| `conditions`    | список `Condition`                                                                | нет   | Все должны быть истинны; `[]`           |
| `steps`         | список `Step`                                                                     | да    | От 1 до 16 шагов                        |
| `effects`       | список `Effect`                                                                   | нет   | Применяются после последнего шага; `[]` |
| `on_cancel`     | список `Effect`                                                                   | нет   | `[]`                                    |
| `interruptible` | `Enum<step_boundary, never>`                                                      | да    | Для группы 3                            |
| `graph`         | `Ref<graph>`                                                                      | да    | Граф оценки, выход типа `Unit` = B      |
| `animation`     | `LogicalName`                                                                     | нет   | Для пузыря и отладчика                  |

`Step` = `{id: LocalId, type: имя шага из манифеста, args: объект}`. Аргументы проверяются по сигнатуре шага в манифесте. `Condition` и `Effect` собираются из закрытого набора операций, разделённого по модулям `forge-ai`:

| Модуль | Условия | Эффекты | Уровни |
|---|---|---|---|
| `rules` (общий) | `stock_gte`, `has_tag`, `flag_is`, `time_between`, `all`, `any`, `not` | `stock_add`, `set_flag`, `emit_stimulus` | 1, 2, 3 |
| `village` | `need_below`, `need_above`, `has_trait`, `day_part_is`, `event_phase_is` | `need_add`, `emotion_add` | только 3 |

В коде это перечисления Rust (`Cond<X>`, `Effect<X>` с веткой `Ext(X)` для операций модуля выше; у уровней 1 и 2 `X` пустой тип), а не реестр. `All` и `Any` проверяются в порядке данных с коротким замыканием; эффекты применяются в порядке списка и пишутся в журнал. Данные мира ядро читает через трейт `WorldQuery`, который реализует игра Forge (запасы и теги на начало такта); эффекты применяются в конце такта в порядке `EntityId`. Флаги хранит `forge-ai`, они входят в его снимок. `time_between` и `day_part_is` берут время из часов ядра (`docs/models/время-модель.md`). Новая операция добавляется только с новой версией схемы.

| Поле           | Тип                                                     | Обяз. | Правило                                 |
|----------------|---------------------------------------------------------|-------|-----------------------------------------|
| `priority`     | `Int`                                                   | да    | От 0 до 100, для наложения и расписаний |

`Phase` = `{id: LocalId, duration: Minutes или {until: TimeOfDay}, weights: словарь категория → Real, actions: список {action: Ref<action>, bucket: LocalId}, jobs: список Ref<job>, schedule: Ref<schedule> или null}`.

### schedule

| Поле      | Тип                                                                           | Обяз. | Правило                                                                              |
|-----------|-------------------------------------------------------------------------------|-------|--------------------------------------------------------------------------------------|
| `blocks`  | список `{from: TimeOfDay, to: TimeOfDay, kind: Enum<sleep, work, free, any>}` | да    | Блоки покрывают сутки без пропусков и наложений, блок может переходить через полночь |
| `weights` | словарь `kind → словарь категория → Real`                                     | да    | Множители категорий в каждом блоке                                                   |

### trait, archetype, stimulus, reaction

- `trait`: `modifiers` — список `{target: Ref<need|action|stimulus>, field: Enum<decay, weight, sensitivity>, mul: Real}`.

- `archetype`: `mode` (`Enum<life, choice>`, по умолчанию `life`), `think_ticks` (`Int` ≥ 1, только для `choice`), `move_speed` (`Real` > 0, клеток в секунду времени мира; без поля берётся из `project.json`), `traits` (список `Ref<trait>`), `category_weights` (категория → `Real` от 0 до 4), `schedule` (`Ref<schedule>`), `curves` (подмена кривых: `Ref<curve>` → `Ref<curve>`).

- `stimulus`: `channels` (список каналов манифеста), `radius` (`Tiles`), `duration` (`Minutes`), `interrupts` (`Bool`), `strength` (`Unit`).

- `reaction`: `stimulus` (`Ref<stimulus>`), `filter` (`Condition`), `graph` (`Ref<graph>`), `response` (список `Effect` или `{action: Ref<action>, bucket: LocalId}`), `memory_minutes` (`Minutes`), `cooldown` (`Minutes`).

## Модель графа

Файл графа хранит только логику. Координаты нод и комментарии лежат в `layout/` с тем же именем.

| Поле      | Тип                                                      | Правило                                                                                         |
|-----------|----------------------------------------------------------|-------------------------------------------------------------------------------------------------|
| `kind`    | `Enum<utility, reaction, subgraph>`                      | Определяет набор допустимых выходов                                                             |
| `nodes`   | список `{id: LocalId, op: имя операции, params: объект}` | До 256 нод                                                                                      |
| `edges`   | список `{from: "нода.порт", to: "нода.порт"}`            | К входному порту идёт не больше одной связи, типы портов совпадают или допускают автоприведение |
| `outputs` | словарь имя → `"нода.порт"`                              | Для `utility` ровно один выход `score` типа `Unit`                                              |
| `inputs`  | список `{id: LocalId, type: PortType}`                   | Только у `subgraph`: внешние порты                                                              |

Типы портов (`PortType`): `unit`, `real`, `bool`, `entity` (ссылка на жителя или объект мира), `flow` (последовательность в графах реакций), `tag`. Автоприведение разрешено только `unit → real` и `bool → unit` (0 или 1). Всё остальное требует явной ноды-переходника.

Правила: графы `utility` ацикличны; подграфы не вызывают себя ни прямо, ни через цепочку; все ноды должны вести к выходу, иначе валидатор выдаёт предупреждение «мёртвая ветка». Набор операций закрытый и версионируемый: входы из манифеста, `curve`, `mul`, `add`, `min`, `max`, `lerp`, `compensate`, `compare`, `and`, `or`, `not`, `select`, `subgraph`, плюс для реакций `sequence`, `wait`, `emit`, `start_action`.

## Манифест

Граница между данными ИИ и игрой Forge это один файл `manifest.json`. Его собирает Forge из модулей игры: что игра умеет и под какими именами. Пишется он автоматически, руками его не правят.

| Что | Содержимое |
|---|---|
| Входы | `{id, type: PortType, args}`: например `light_level`, `stock_shortage` |
| Шаги | `{id, version: semver, args: схема, result_reasons: список}`: `goto_slot`, `take_item`, `play_animation`, `say`. У `goto_slot` необязательный аргумент `speed_mul` (`Unit` от 0,25 до 4, по умолчанию 1: бегство, бег на праздник) |
| Каналы восприятия | `sight`, `hearing`, `rumor` и каналы модулей |
| Логические имена | Анимации (из сцен Motif), звуки и эффекты, которые могут понадобиться шагам |

Правила для модуля «Жители»:

1.  Каждый шаг и вход манифеста имеет реализацию в Forge, на Rust или на Luau. Без неё игра не запускается и называет недостающее имя.

2.  Позиции передаются в клетках, время в тактах. Перевод в пиксели и кадры делает модуль.

3.  Сущности мира рантайм знает по своим числовым id (`EntityId`, 64 бита). Связь с объектами Forge держит модуль.

4.  Модуль не меняет состояние ИИ напрямую. Он только отвечает на запросы шагов, отдаёт значения входов и публикует события мира через поток входов.

## Состояние в рантайме

Рантайм работает с тремя структурами данных. Все три сериализуются и в читаемый JSON для отладки, и в двоичный вид для релиза, с одинаковым содержимым.

**Снимок (сохранение).**

| Часть                      | Что хранит                                                                                                    |
|----------------------------|---------------------------------------------------------------------------------------------------------------|
| Заголовок                  | `snapshot_format`, хэш манифеста, версия пакета, `simulation_tick`, `session_id`                  |
| Часы                       | Игровая дата и минута суток                                                                                   |
| Генераторы случайных чисел | Состояние каждого RNG (на жителя и на систему), алгоритм PCG32                                                |
| Жители                     | `EntityId`, архетип, черты, потребности, эмоции, память, флаги, позиция в клетках, текущий экземпляр действия |
| Экземпляр действия         | `ActionInstanceId` (в `act` он передаётся как `OwnerToken`), `Ref<action>`, объект и слот, номер шага, такт начала шага, группа и B на момент выбора   |
| Объекты                    | `EntityId`, `Ref<object>`, запасы, брони слотов с владельцем `ActionInstanceId`                               |
| События                    | `Ref<event>`, фаза, часы фазы, пауза, время старта                                                            |
| Доска заданий              | Задания, их источник, исполнитель, приоритеты ролей по жителям                                                |
| Стимулы                    | Активные стимулы с тактом появления и источником                                                              |

Исполнения шагов в снимок не входят: после загрузки начинается новый `session_id`, и рантайм заново выдаёт запрос текущего шага.

**Поток входов.** Упорядоченный список записей `{tick, kind, payload}`. Виды: `step_result` (`execution_id`, статус, причина), `world_event` (например, начался пожар), `player_command` (смена приоритета на доске, постройка), `spawn` и `despawn`, `input_value` (значение входа от Forge, если оно зависит от мира). Снимок, поток и сид вместе однозначно задают журнал.

**Журнал решений.** Одна запись на размышление: `tick`, житель, активная группа, список кандидатов `{action, object, admissible, failed_condition, B, S, factors}`, победитель, причина (`chosen`, `kept`, `interrupted_by`, `refused`), текущий шаг и ожидаемый `execution_id`. Для сравнения журналов используется канонический JSON без полей `factors`, чтобы вид отладочной раскладки не ломал сравнение.

## Версии, миграции и ошибки

- **Три независимые версии.** Формат проекта (`format`), схема каждого вида ресурса (`schema: "action/1"`) и формат снимка (`snapshot_format`). Каждая растёт на единицу при несовместимом изменении.

- **Миграции.** Для каждого шага N → N+1 есть функция миграции и тест на примере. Редактор перед миграцией копирует проект в `.backup/<дата>/` и никогда не пишет поверх исходника без копии. Игра мигрирует снимок в памяти, а файл сохранения перезаписывает только при следующем сохранении.

- **Несовместимый снимок.** Если хэш манифеста другой и миграции нет, загрузка отклоняется с ошибкой `E_SNAPSHOT_CONTRACT`, а файл остаётся нетронутым. Переименованные id разрешаются через `renames.json`, удалённые действия отменяются при загрузке по правилам горячей перезагрузки.

Формат ошибки валидатора: `{code, severity: Enum<error, warning>, file, resource, path, node, message_key}`. Поле `path` записано в формате JSON Pointer, поэтому редактор по нему переходит к полю или ноде.

| Код                   | Уровень        | Когда                                                        |
|-----------------------|----------------|--------------------------------------------------------------|
| `E_SCHEMA`            | ошибка         | Поле не того типа, неизвестное или отсутствует обязательное  |
| `E_ID_FORMAT`         | ошибка         | id не соответствует формату или имени файла                  |
| `E_ID_DUPLICATE`      | ошибка         | Два ресурса или две ноды с одним id                          |
| `E_REF_MISSING`       | ошибка         | Ссылка на несуществующий ресурс                              |
| `E_REF_KIND`          | ошибка         | Ссылка на ресурс не того вида                                |
| `E_RANGE`             | ошибка         | Число вне диапазона или с лишними знаками                    |
| `E_PORT_TYPE`         | ошибка         | Связь между несовместимыми портами                           |
| `E_GRAPH_CYCLE`       | ошибка         | Цикл в графе оценки или в вызовах подграфов                  |
| `E_MANIFEST`          | ошибка         | Шаг, вход, канал или логическое имя не объявлены в манифесте |
| `E_IMPL_MISSING`      | ошибка         | Шаг, вход или тег из данных не реализован в игре Forge или не объявлен в манифесте |
| `E_OP_LEVEL`          | ошибка         | Операция модуля `village` в данных уровня 1 (машина состояний) или 2 (архетип с `mode: choice`); в сообщении файл, путь к операции и уровень |
| `E_SCHEDULE_GAP`      | ошибка         | Блоки расписания не покрывают сутки или накладываются        |
| `E_LOC_MISSING`       | ошибка         | Нет строки для ключа на основном языке                       |
| `E_SNAPSHOT_CONTRACT` | ошибка         | Снимок снят с другим манифестом, миграции нет                |
| `W_DEAD_BRANCH`       | предупреждение | Нода не влияет на выход                                      |
| `W_ALWAYS_ZERO`       | предупреждение | Выход графа равен 0 при любых входах из диапазона            |
| `W_UNUSED`            | предупреждение | На ресурс никто не ссылается                                 |
