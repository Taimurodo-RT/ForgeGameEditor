# Скрипты и ноды: архитектура

Дата: 2026-10-03. Шаг 6 дорожной карты. Связано: [core-architecture.md](core-architecture.md).

## Главная задача

Библиотека нодов будет расти годами: сотни нод от нас, от модулей и от авторов игр.
Поэтому ядро не должно знать ни одной конкретной ноды. Ядро знает только **как
устроена нода вообще**, а сами ноды лежат в данных. Добавить, переименовать или
переделать ноду — это правка файла, а не C++ и не пересборка движка. Старые графы
при этом не ломаются.

## Слои

```
 граф (JSON, редактор)            ← что видит автор
   │  библиотека нодов (данные)    ← что значит каждая нода
   ▼
 компилятор графа → Luau + карта «нода ↔ строка»
   ▼
 среда Luau (ScriptHost)          ← песочница, ошибки, ожидания, горячая замена
   │  API движка (ScriptApi)       ← одно описание даёт и функцию Luau, и ноду
   ▼
 ECS, мир, симуляция, время (шаги 3–5)
```

Каждый слой можно использовать отдельно: продвинутый автор пишет на Luau напрямую,
а ноды — это тот же Luau, только собранный из блоков.

## 1. Среда Luau (`engine/script`)

- **Одна VM на симуляцию.** Скрипты исполняются в фазе логики тика, в главном потоке.
  Тяжёлое (поиск врагов в радиусе, пути, физика) делают нативные системы пакетами;
  скрипт ими управляет.
- **Песочница.** Нет `io`, `os`, `debug`, загрузки файлов. Глобальные библиотеки
  заморожены (`luaL_sandbox`), каждый скрипт получает своё окружение.
- **Ошибка не роняет игру.** Ошибка ловится, привязывается к ноде через карту строк и
  выключает только этот обработчик у этого объекта. В редакторе тест-прогон
  останавливается и подсвечивает ноду; в собранной игре ошибка пишется в лог.
- **Защита от зависаний.** Бюджет времени на вызов (по умолчанию 5 мс). Бесконечный
  цикл прерывается с понятной ошибкой «скрипт выполнялся слишком долго».
- **Ожидания по игровому времени.** «Ждать 2 с» — это корутина, которую будит
  планировщик. Время берётся из шага 5: замедление, пауза и перемотка действуют и
  на скрипты; у объектов «вне времени» — своё время. У ноды есть галочка «реальное время».
- **Состояние живёт в данных, а не в Luau.** Переменные объекта хранятся в
  компоненте `ScriptVars` (сохраняется вместе с чанком, видно в инспекторе).
  Поэтому горячая замена скрипта не теряет состояние, а сохранение игры не
  требует сериализации Luau.
- **Горячая замена.** Новый текст скрипта компилируется; если ошибок нет, модуль
  подменяется, обработчики переподписываются. Идущие ожидания старой версии
  доигрывают до конца.
- **События.** Скрипт подписывается на события: старт, тик, вход и выход из
  триггера, удар, смерть, своё сообщение. Движок кладёт события в очередь, хост
  раздаёт их подписчикам в конце тика (детерминированный порядок).

## 2. API движка (`ScriptApi`)

Одна запись описывает функцию движка один раз:

```
имя: "entity.play_sound"   категория: "Звук"   иконка: "volume_up"
параметры: actor: Entity, sound: Asset<Sound>, volume: number = 1 (0..2)
возвращает: —
подписи: ru / en
```

Из этой записи автоматически получаются:
- функция Luau (`forge.entity.play_sound(e, s, 0.8)`),
- нода «Проиграть звук» с пинами нужных типов и значениями по умолчанию,
- проверка типов в компиляторе и подсказки в редакторе.

Кроме того, автоматически появляются ноды «Взять поле» и «Задать поле» для каждого
компонента, описанного через рефлексию (`FORGE_REFLECT`). Описал компонент `Health` —
получил ноды «Здоровье: текущее» без единой строчки кода для нод.

## 3. Библиотека нодов (данные)

Нода описана записью `NodeDef` в файле `*.nodes.json`. Файлы лежат в модулях
(стандартный модуль движка, модули жанров, проект). Пример:

```json
{
  "id": "std.flow.if", "version": 1,
  "kind": "flow", "category": "Поток", "icon": "call_split",
  "title": { "ru": "Если", "en": "If" },
  "inputs":  [{ "id": "cond", "type": "bool", "title": { "ru": "Условие" } }],
  "slots":   [{ "id": "then", "title": { "ru": "Тогда" } },
              { "id": "else", "title": { "ru": "Иначе" } }],
  "lua": "if {in:cond} then\n    {slot:then}\nelse\n    {slot:else}\nend"
}
```

Виды нод (как в макете «Анатомия нод»): событие, действие, чистая функция, поток
(ветки и циклы со слотами и выходами), переменная, макро (нода из подграфа), а для
редактора — заметка, группа, перенаправитель.

Как нода получает своё поведение, по выбору:
- `call` — имя функции из `ScriptApi` (большинство нод);
- `lua` — шаблон Luau с подстановками `{in:пин}` (значение входа), `{out:пин}`
  (переменная выхода), `{slot:имя}` (блоки слота), `{body}` (у событий: что идёт
  дальше), `{self}`, `{uid}`, `{pure}` (у циклов: пересчитать входы на каждом проходе);
- `graph` — подграф: высокоуровневая «человеческая» нода разворачивается в
  низкоуровневые. Так делаются ноды «по идее», которые можно раскрыть и настроить подробно.

**Авторские ноды.** Любой граф можно пометить «сделать нодой»: его входы и выходы
становятся пинами, и он появляется в палитре. Библиотеку можно расширять, не выходя
из редактора.

### Устойчивость к правкам библиотеки

- У ноды и у каждого пина **постоянный id**. Подпись можно менять как угодно, граф
  ссылается на id.
- В графе у каждой ноды записана версия её описания. Если библиотека новее, работают
  **миграции** из описания: переименование пинов, новые значения по умолчанию, замена
  ноды другой (`replaced_by`). Это тот же подход, что у компонентов в рефлексии.
- Если описание ноды пропало (модуль удалён), нода не исчезает из графа: она
  становится «потерянной», хранит свои значения и связи, а компилятор сообщает об
  ошибке на ней. Вернули модуль — всё снова работает.
- Типы пинов берутся из рефлексии (число, логика, строка, вектор, цвет, объект,
  ссылки на ассеты, перечисления, компоненты). Явная таблица неявных
  преобразований (целое → число, объект → «есть ли объект»).

## 4. Граф

JSON-документ: ноды (uid, id и версия описания, позиция, значения неподключённых
пинов, содержимое слотов — упорядоченные списки uid вложенных блоков) и связи
(`uid.пин → uid.пин`). Блок в слоте — это та же нода, просто без своей позиции.
Поэтому слоты и провода — одна модель, и блок можно вытащить из слота на поле.

Один формат графа служит скриптам, диалогам и машине анимаций (как в макете): у
них разные библиотеки нод и разные компиляторы, но общий документ, редактор,
отмена/повтор и миграции.

## 5. Компилятор графа → Luau

1. **Проверка:** неизвестные ноды, несовпадение типов, обязательные пины без
   значения («Подключите актёра»), циклы в данных. Ошибки привязаны к ноде и пину.
2. **Поток:** каждое событие становится функцией-обработчиком. Цепочка «Далее»
   превращается в последовательность операторов, слоты — во вложенные блоки.
   Если в один вход сходится несколько выходов, общая часть становится локальной
   функцией (в Luau нет `goto`).
3. **Данные:** чистые ноды вычисляются прямо перед блоком, которому они нужны, каждый
   раз, когда он выполняется (после «Сдвинуть» «Позиция» уже новая). Нода, нужная
   блоку дважды, считается один раз.
4. **Карта строк:** каждая строка Luau помнит, какой ноде она принадлежит. По ней
   ошибки, точки останова и пошаговая отладка показываются прямо на графе.
5. **Режим профилирования:** компилятор добавляет вокруг нод замеры, и профилировщик
   показывает время и число вызовов каждой ноды. В обычной сборке замеров нет.

## 6. Порядок работы на шаге 6

- **6a — среда Luau:** зависимость, `ScriptHost`, песочница, бюджет, ошибки,
  ожидания по игровому времени, события, `ScriptVars`, доступ к компонентам через
  рефлексию, реестр `ScriptApi`, тесты и бенчмарк.
- **6b — ноды:** `NodeDef`, `NodeLibrary` (загрузка из файлов, миграции, ноды из
  рефлексии и `ScriptApi`), документ графа, компилятор, карта строк, профилирование
  нод, стандартная библиотека (события, поток, логика, математика, переменные,
  объекты, время).
- **6c — демо:** дверь, сундук и враг собраны из нод (графы лежат файлами), горячая
  замена по изменению файла, время нод в заголовке и в профилировщике.

Сделано: `apps/script_demo` — существа, дверь, сундук и монеты целиком на графах из
`apps/script_demo/graphs`. Дверь пользуется нодой «Колонна двери», которая сама
является графом. Тест `the demo's graphs compile and work` следит, чтобы графы демо
собирались при любых правках библиотеки.

## 7. Как добавить ноду

1. Функция движка: `api.add("имя", &функция)` с подписями и параметрами — нода
   `api.имя` появится сама.
2. Поле компонента: описать компонент через `FORGE_REFLECT` и открыть скриптам
   (`ScriptHost::expose<T>()`) — появятся ноды `comp.Тип.поле.get` / `.set`.
3. Всё остальное: запись в `*.nodes.json` (стандартная библиотека —
   `engine/script/nodes/std.nodes.json`, встроена в движок). Модуль может
   переопределить любую ноду по id.
4. Переименовали пин или заменили ноду — повысить `version` и добавить запись в
   `migrations`; старые графы обновятся при загрузке (`migrate`).

RmlUi). Формат, библиотека и компилятор, сделанные сейчас, — его основа.
